# Forgetting Evidence Service

这是一个面向后端系统的机器遗忘证据服务，用于记录删除请求、执行状态和可验证回执。当前提供可运行的 Python 包、健康检查入口、删除请求的受理与查询 HTTP API（SQLite 持久化）、请求存储层上的可持久化状态机（状态推进与状态查询）、存储层上的删除执行编排（领取-租约-续期-完成与执行记录）、存储层上的删除回执生成、核验与可恢复密钥轮换，以及存储层上的旧版执行租约可恢复批量迁移（按租户以持久化游标分批把旧版租约簿记补齐为当前尝试与唯一在租凭证簿记，不改变请求状态、时间、尝试结果、领取候选或对账结果；同游标并发续查由唯一获胜事务整页原子推进，竞争调用以空项列表回放获胜事务提交后的进度；重复迁移每项只落一次升级，空批次也保留稳定进度），以及存储层上的跨重启外部可信锚点、全链核验、可恢复的锚点密钥代次轮换与只读批量审计完整性巡检（受理与每次实际状态变化的有序事件、请求链头、外部锚点与全局锚点原子落定，锚点按其生成时代次绑定密钥、只读全链核验与只报告原因的恢复诊断、按租户可恢复游标分批逐项核验已落定审计链；同一租户、批次与游标并发续查时由唯一获胜事务整页原子推进巡检簿记，竞争调用以空项列表回放获胜事务提交后的进度；另有只读取批次计数的只读摘要入口、按原因聚合的只读逐批指标入口与跨批次原因汇总入口），以及存储层上的审计证据包导出与脱离数据库的异地核验和恢复诊断（按租户与请求编号把当前已落定链冻结为单行紧凑 JSON 证据包，异地仅凭证据包文本与调用方保管的锚点秘密代次映射离线判断可信性；诊断只读取传入材料，不连接存储实例、不创建批次、不修改任何历史证据，返回可信标记与按 Unicode 码点字典序排列的稳定原因码列表，缺少数据库时有效证据包结论仍为可信；证据包导出另经 `GET /requests/{request_id}/audit-bundle` 只读 HTTP 入口按字节原样开放，离线核验与诊断仍只在存储层开放），以及存储层上的策略目录版本化管理（普通规则与主体例外按既有保留期语义规范化后发布为只读不可变版本，版本号为每租户从 1 起连续签发的正整数；同租户相同规范化目录重复发布复用首次版本与生效时间，不同目录签发下一版本；版本行、规则行与例外行在同一事务全部写入成功后才可见，相同目录并发发布只落一次版本、不同目录并发发布仅一个获胜而竞争调用抛 `PolicyCatalogConflict`；读取可指定版本或默认读取最新版本，审计按版本升序返回只含版本、生效时间、规则/例外计数与状态的历史摘要而不含主体明细；三入口均返回单行紧凑 JSON 并以一个换行结束，读取与审计严格只读，不新增健康命令；保留期判定入口亦可显式指定已发布目录版本作为唯一目录来源（缺省沿用调用期目录输入，两种来源不得同时给出），在单个只读事务的一致快照中按既有优先级语义给出可追溯到确定版本的判定结果，不发布版本、不写库，也不改变既有受理、状态、执行、回执、锚点、巡检与敏感信息边界；保留期判定另有只读逐范围决策证据入口 `resolve_retention_trace`，入参与目录来源二选一规则与聚合判定一致，输出单行紧凑 JSON（目录来源、查询主体、规范化范围、有效天数、胜出策略、原因、命中例外标记与逐范围证据），只返回主体与规范化范围而不返回原始范围序列，不新增任何业务字段到聚合判定、不新增健康命令；其已发布版本证据另经只读 HTTP 入口 `GET /policy-catalog/retention-trace` 公开），以及存储层上的逐范围删除墓碑与范围化完成台账（在有效租约下登记各适配器删除结果，每项含适配器、命中规范化范围、操作编号、deleted/absent 结果与 64 位小写十六进制证明摘要，不保存原始对象或证明正文；相同列表重放返回首次落定的 recorded_at 与摘要，操作编号冲突、同范围结果矛盾或编号跨请求跨租户复用抛 TombstoneConflict 且不改台账；范围化完成仅接受 completed/failed，completed 要求每个规范化范围恰有一个墓碑才原子写终态、evidence_digest 与执行记录，缺失、重复或多余抛 TombstoneUnavailable，failed 不要求覆盖且重复调用沿用首次结果；查询按规范化范围再按适配器返回墓碑、recorded_at 与 evidence_digest；分页墓碑查询另经 HTTP 只读开放，不新增健康命令）。状态推进、执行编排中的领取/续期/完成/对账/迁移、回执、锚点核验、回执密钥轮换、锚点密钥轮换、巡检摘要、跨批次指标、证据包导出、异地核验、离线诊断、删除墓碑登记与范围化完成能力只在存储层开放；HTTP 除受理与受理回执查询外，仅新增租户范围请求摘要分页查询、当前状态、执行记录三个严格只读可观测入口、删除墓碑分页只读公开入口、请求级完整性结论只读入口与请求级状态时间线只读入口（`GET /requests/{request_id}/evidence`：在单个已提交快照内返回当前状态、状态事件数、持久化链头与同快照逐事件重放的核验结论，链头非法文本时为 `null`，事件删改插重排或跨请求/租户重绑时仍 200 且 `verified=false`，严格只读，不推进状态、不创建尝试、不写入簿记、不返回租约凭证或 worker 身份），以及请求级状态时间线只读入口（`GET /requests/{request_id}/audit-timeline`：在单个已提交快照内按发生顺序返回受理与每次实际状态变化的状态事件，每项只含 `status` 与 `occurred_at`，首项受理、重复推进不追加、时间为 UTC RFC3339 且不倒退、末项状态等于当前持久化状态；执行尝试、墓碑、回执与审计链事件不混入；事件损坏、链头替换、状态分裂或快照不一致一律 503，绝不返回半份时间线或伪造事件，严格只读且重启后顺序与时间不变），以及批量审计巡检扫描与逐批原因聚合指标入口（`GET /audit-inspection`，鉴权开启时要求 `request:reconcile` 且限本人租户），不新增任何执行、回执生成与核验、密钥轮换、锚点、巡检摘要、跨批次指标或墓碑相关其他 HTTP 入口；证据包能力中仅导出经 `GET /requests/{request_id}/audit-bundle` 只读开放，离线核验与诊断不新增 HTTP 入口；删除执行回执能力中仅已固化首次回执文本经 `GET /requests/{request_id}/deletion-receipt` 只读开放，回执生成、核验与密钥轮换仍只在存储层开放。

运行健康检查：

```bash
PYTHONPATH=src python3 -m forgetting_evidence health
```

启动 HTTP 服务（以数据库路径、监听地址和端口启动；启动时自动创建所需表）：

```bash
PYTHONPATH=src python3 -m forgetting_evidence serve ./data/evidence.db 0.0.0.0 8080
# 也可使用命名参数
PYTHONPATH=src python3 -m forgetting_evidence serve --db ./data/evidence.db --host 0.0.0.0 --port 8080
```

可选令牌鉴权与 RBAC（不提供 `--auth-file` 时维持无鉴权契约与健康命令；提供后仅在启动时读取该文件一次，配置不合规或文件缺失/不可读时**不绑定端口**，标准错误只输出 `auth_config_invalid`，进程以状态码 2 退出）：

```bash
PYTHONPATH=src python3 -m forgetting_evidence serve --db ./data/evidence.db --host 0.0.0.0 --port 8080 --auth-file ./config/auth.json
```

鉴权配置为 UTF-8 JSON 对象，含 `principals` 键，其每项含非空字符串 `token`、非空字符串 `tenant_id` 与非空数组 `roles`；`roles` 元素互异，且只能取 `request:submit`、`request:read` 与 `request:reconcile`；令牌不得重复。例：

```json
{"principals":[{"token":"token-for-a","tenant_id":"tenant-a","roles":["request:submit","request:read","request:reconcile"]},{"token":"read-only-b","tenant_id":"tenant-b","roles":["request:read"]}]}
```

启用鉴权后，`Authorization` 必须为 `Bearer <已配置令牌>`；缺少或畸形授权头、令牌未配置返回 `401 {"error":"unauthorized"}`。角色不足或目标租户不是其 `tenant_id` 返回 `403 {"error":"forbidden"}`：`POST /requests` 要求 `request:submit`，目标租户取请求体 `tenant_id`；`GET /requests`、`GET /requests/{request_id}`、`GET /requests/{request_id}/status`、`GET /requests/{request_id}/execution-log`、`GET /requests/{request_id}/tombstones`、`GET /requests/{request_id}/evidence`、`GET /requests/{request_id}/audit-timeline`、`GET /requests/{request_id}/audit-bundle`、`GET /requests/{request_id}/deletion-receipt` 与 `GET /audit-health` 均要求 `request:read`，`POST /requests/{request_id}/reconcile`、`POST /reconcile` 与 `GET /audit-inspection` 均要求 `request:reconcile`；后三类入口的目标租户沿用 `X-Tenant-Id` 非空优先、否则取最后一个非空 `tenant_id` 查询参数的既有规则。鉴权在已匹配路径之后（未知路径仍 404、不支持方法仍 405）、但先于载荷校验与存储访问执行。无 `--auth-file` 时 `Authorization` 头被忽略。重启后的授权结果只由同一份配置决定；令牌、角色与鉴权配置只存在于进程内存，绝不写入数据库、状态、执行、回执、审计事件、锚点或证据包，也不进入响应、异常或日志。


业务入口（HTTP 十二个；只读可观测/导出/巡检入口与对账动作外，其余能力均只在存储层开放）：

- `POST /requests`：受理删除请求。请求体为 JSON：`tenant_id`、`subject_id`、`idempotency_key` 均为非空字符串，`scopes` 为元素互异的非空字符串数组。
  成功返回单行 JSON，依次含 `request_id`（UUID）、`status`（`accepted`）、`created_at`（UTC RFC3339），并以换行结尾。
  同租户同幂等键同主体、同范围集合（与顺序无关）的重复提交返回首次回执；主体或范围集合不同返回 `409 {"error":"idempotency_conflict"}`。
- `GET /requests`：租户范围的请求摘要分页查询，严格只读。租户沿用 `X-Tenant-Id` 请求头或 `tenant_id` 查询参数的既有规则；可选查询参数 `status`（逗号分隔的互异状态值，取 `accepted`、`processing`、`completed`、`failed`，缺省为全部）、`created_from`（含边界）与 `created_to`（不含边界，均为 RFC3339 UTC）、`cursor`（不透明续查值）与 `limit`（缺省 100，仅接受 1 至 1000 的整数）。返回单行 JSON，恰含 `items` 与 `next_cursor`；每项恰含 `request_id`、`status`、`created_at`，按 `created_at`、`request_id` 升序；`next_cursor` 在列表结束时为 `null`，否则从末项后续查。游标绑定同一租户与规范化筛选条件，跨租户或跨筛选条件复用、未知查询参数、`status` 重复值或任何非法筛选参数均返回 `400 {"error":"invalid_request"}`；存储故障返回 `503 {"error":"storage_unavailable"}`。列表不推进状态、不写簿记，不含主体、范围、幂等键、执行凭证、SQL 或路径；静态数据重启后分页结果与游标位置一致。
- `GET /requests/{request_id}`：按请求编号查询本租户的**受理回执**。租户通过 `X-Tenant-Id` 请求头或 `tenant_id` 查询参数指定，命中时返回与受理时完全一致的回执；该回执在状态推进后保持不变，始终为受理时的 `accepted` 记录（请求编号与受理时间也保持首次值）。
- `GET /requests/{request_id}/status`：只读查询请求**当前状态**。返回单行 JSON，字段按 `request_id`、`status`、`created_at` 顺序排列并以一个换行结束；`status` 读取数据库当前状态，`created_at` 保持原始受理时间。严格只读：不推进状态、不创建尝试、不写入簿记，重启后与持久化记录一致。
- `GET /requests/{request_id}/execution-log`：只读查询请求的**执行记录**。返回单行 JSON，恰含 `request_id` 与 `attempts`；`attempts` 按 `attempt_number` 从 1 递增排列，每项恰含 `attempt_number`、`claimed_at`、`lease_expires_at`、`result`、`completed_at`。未结束尝试的 `result` 与 `completed_at` 为 `null`；已结束尝试使用已有的 `completed` 或 `failed` 结果及完成时间。严格只读，不返回租约凭证、worker 身份、主体、范围或其他请求信息，重启后与持久化记录一致。
- `GET /requests/{request_id}/tombstones`：只读分页公开本租户该请求的**删除证明**。租户沿用 `X-Tenant-Id` 非空优先、否则取最后一个非空 `tenant_id` 查询参数的既有规则；仅接受 `cursor` 与 `limit` 查询参数（`limit` 缺省 100，仅接受 1 至 1000 的非布尔整数；`cursor` 只接受先前返回的续查值）。成功返回 `200` 单行 JSON 并以一个换行结尾，顶层字段依次为 `request_id`、`tombstones`、`recorded_at`、`evidence_digest`、`next_cursor`；`tombstones` 仅含当前页，按规范化范围 Unicode 码点序再按 `adapter_id` 升序，每项恰含 `adapter_id`、`scope`、`operation_id`、`outcome`（`deleted` 或 `absent`）、`proof_digest`（64 位小写十六进制）与 `recorded_at`；顶层 `recorded_at` 与 `evidence_digest` 始终描述全台账（台账为空时均为 `null`），`next_cursor` 在台账还有后项时从本页末项后续查、否则为 `null`。未知或重复查询参数、非法 `limit`，以及空、格式错误或绑定其他租户、其他请求、已变化快照的 `cursor`，统一返回 `400 {"error":"invalid_request"}` 且不写库；非法、未知或跨租户请求编号返回 `404 {"error":"not_found"}`；存储故障或台账损坏返回 `503 {"error":"storage_unavailable"}`，绝不返回半页或伪摘要。该资源的非 GET 方法返回 `405 {"error":"method_not_allowed"}` 并带 `Allow: GET`，HEAD 不返回正文，更深路径返回 `404 {"error":"not_found"}`。游标重放返回字节一致结果；查询严格只读：不推进状态、不创建尝试、不登记墓碑、不改变审计链，也不泄露主体、原始对象、证明正文、幂等键、worker、凭证、SQL 或路径。
- `POST /requests/{request_id}/reconcile`：对**单个请求**执行对账，调用存储层既有 `reconcile_execution` 语义（领取、租约、补写执行记录、终态保持与跨重启语义均不改写）；批量对账另经 `POST /reconcile` 开放。入口不接收业务参数：`Content-Length` 缺省或为 `0` 表示无正文，其他正文一律返回 `400 {"error":"invalid_request"}`。成功返回 `200` 与状态查询同形的单行 JSON，字段恰为 `request_id`、`status`、`created_at`（顺序固定、换行结尾），为对账后的当前记录；不暴露主体、范围、幂等键、worker、凭证或尝试明细。租户沿用 `X-Tenant-Id` 非空优先、否则取最后一个非空 `tenant_id` 查询参数的既有规则，目标租户缺失或空返回 `400 {"error":"invalid_request"}`；请求编号格式非法、未知、尚未受理或跨租户统一返回 `404 {"error":"not_found"}`；存储层参数错误返回 `400 {"error":"invalid_request"}`，存储故障或记录损坏返回 `503 {"error":"storage_unavailable"}`，失败不留下半成响应或额外业务记录。该资源的非 POST 方法返回 `405 {"error":"method_not_allowed"}` 并带 `Allow: POST`，HEAD 不返回正文；更深路径仍为 `404 {"error":"not_found"}`。重复调用不改变稳定终态、历史尝试或既有时间；并发调用由存储层原子提交决定唯一结果。
- `POST /reconcile`：按租户**批量对账**待收敛请求，调用存储层既有 `reconcile_batch` 语义（逐项收敛、持久化批次与游标、跨重启续跑语义均不改写）。租户沿用 `X-Tenant-Id` 非空优先、否则取最后一个非空 `tenant_id` 查询参数的既有规则；请求体必须为空（`Content-Length` 缺省或为 `0` 表示无正文，其他正文一律返回 `400 {"error":"invalid_request"}`），仅接受 `cursor` 与 `limit` 查询参数（`limit` 缺省 100，仅接受 1 至 1000 的整数）；无 `cursor` 创建新持久化批次，携带 `cursor` 从该批次的已提交位置续跑。成功返回 `200` 单行 JSON，顶层恰含 `batch_id`、`next_cursor`、`finished`、`items`（顺序固定、换行结尾）：未完成时 `next_cursor` 为续跑游标字符串，结束时为 `null`；`finished` 为布尔；`items` 按 `created_at`、`request_id` 顺序列出本次收敛的非 `accepted` 请求，每项恰含 `request_id` 与 `status`。`accepted` 只推进位置、不进入 `items`，不产生尝试、回执或状态事件；有有效租约的 `processing` 保持原状，租约过期或无可解释租约的原子补偿为 `failed` 并释放租约；`completed`、`failed` 不变；重试同一游标不重写已提交项。扫完候选时 `finished` 为 `true` 且 `next_cursor` 为 `null`（`items` 可为空），受 `limit` 截断时返回 `false` 与续跑游标。未知或重复查询参数、空租户、非法 `limit`、非空请求体、格式错误、未知或跨租户 `cursor` 统一返回 `400 {"error":"invalid_request"}` 且不推进批次、不改变请求；数据库不可用、批次损坏或提交失败统一返回 `503 {"error":"storage_unavailable"}`。该资源的非 POST 方法（含 GET）返回 `405 {"error":"method_not_allowed"}` 并带 `Allow: POST`，HEAD 不返回正文；更深或并列路径仍为 `404 {"error":"not_found"}`。鉴权开启时要求 `request:reconcile` 角色，鉴权先于参数与存储；鉴权关闭时维持公开调用。
- `GET /requests/{request_id}/evidence`：只读查询删除请求的**请求级完整性结论**。租户沿用 `X-Tenant-Id` 非空优先、否则取最后一个非空 `tenant_id` 查询参数的既有规则，鉴权要求 `request:read`。成功返回 `200 application/json`，正文为一行紧凑 UTF-8 JSON 加一个换行，字段固定依次为 `request_id`、`status`、`event_count`、`chain_hash`、`verified`：`request_id` 为被查询请求，`status` 与 `event_count` 是同一数据库快照中的当前状态与状态事件数，`chain_hash` 是该快照在请求记录上持久化的 64 位小写十六进制链头（持久化值不是合法 SHA-256 文本时为 `null`），`verified` 仅在同一快照内逐事件重算哈希全部一致、序号从 0 连续、末事件状态等于当前状态且末链哈希等于请求记录绑定链头时为 `true`，否则为 `false`。五个字段来自同一个已提交快照（请求行、有序事件与事件计数在单个只读事务内读取），状态推进或并发写入不会让一次响应混合两个事务的结果。请求记录、事件与链头可读时，即使事件被删除、改写、插入、重排或与其他请求/租户重新绑定，仍返回 `200` 且 `verified` 为 `false`；持久化链头不是合法 SHA-256 文本时 `chain_hash` 为 `null` 且 `verified` 为 `false`。请求编号格式非法、不存在或属于其他租户统一返回 `404 {"error":"not_found"}`，不区分缺失与越权；租户缺失或非法返回 `400 {"error":"invalid_request"}`；鉴权失败保持既有 `401 {"error":"unauthorized"}` 与 `403 {"error":"forbidden"}` 的顺序与结果；数据库不可达、读写故障或快照无法完整读取返回 `503 {"error":"storage_unavailable"}`，错误正文只有 `error` 字段，不泄露 SQL、路径、租户、主体、范围内容或令牌。该 GET 严格只读：不创建或修改请求、状态事件、执行尝试、墓碑、回执、策略目录或审计锚点，并保持全部既有公开入口的行为与兼容结果；非 GET 方法返回 `405 {"error":"method_not_allowed"}` 并带 `Allow: GET`，HEAD 不返回正文，更深路径为 `404 {"error":"not_found"}`。
- `GET /requests/{request_id}/audit-timeline`：只读查询请求的**请求级状态时间线**（按发生顺序的状态历史）。租户沿用 `X-Tenant-Id` 非空优先、否则取最后一个非空 `tenant_id` 查询参数的既有规则，鉴权开启时要求 `request:read` 且限于令牌所属租户，鉴权关闭时维持公开读取；入口仅接受 GET，查询字符串只允许单个 `tenant_id`，重复或未知查询参数、缺失或空白租户返回 `400 {"error":"invalid_request"}`。成功返回 `200 application/json`，正文为一行紧凑 UTF-8 JSON 加恰好一个末尾换行，顶层字段固定依次为 `request_id`、`events`：`events` 按发生顺序排列，每项恰含 `status` 与 `occurred_at`；首项恒为 `accepted` 受理事件（其时间即首次受理时间），其后只记录实际状态变化，重复推进当前状态是幂等空操作、不追加事件，`status` 只可能是 `accepted`、`processing`、`completed`、`failed`，相邻状态只能沿固定生命周期迁移（`accepted -> processing -> {completed, failed}`、`accepted -> failed`），`occurred_at` 为规范 UTC RFC3339 文本且在序列中不倒退，末项 `status` 与请求行上当前持久化状态一致。执行尝试、删除墓碑、受理/删除回执与审计链锚点事件都不混入 `events`。请求编号为空、格式非法、不存在或跨租户统一返回 `404 {"error":"not_found"}`，不区分缺失与越权；其他方法返回 `405 {"error":"method_not_allowed"}` 并带 `Allow: GET`，HEAD 为无响应体的 405，更深路径为 `404 {"error":"not_found"}`。请求行、持久化链头与全部有序状态事件在单个只读事务的同一已提交快照内读取，并在渲染前从该快照逐项重放校验（序号自 0 连续、首项受理、相邻状态为生命周期允许的边、状态值域、时间格式与单调性、逐环链哈希、末环等于请求链头、末状态等于当前状态）；数据库不可读、事件损坏或无法取得一致历史时返回 `503 {"error":"storage_unavailable"}`，绝不返回半份时间线、伪造事件或跨事务混合记录，错误正文只含 `error` 字段。重启后同一持久化历史返回相同顺序与相同时间值，重复读取字节一致且不写库；该入口严格只读，不推进状态，不创建执行尝试、墓碑或回执，不写审计链、锚点、策略目录或巡检簿记，其他既有公开入口的响应、行为和错误码保持不变；响应、异常与日志不出现主体、原始范围、幂等键、令牌、领取凭证、worker、SQL 原文或文件路径。
- `GET /requests/{request_id}/audit-bundle`：只读导出该请求已落定审计链的**可脱库验证证据包**。租户沿用 `X-Tenant-Id` 非空优先、否则取最后一个非空 `tenant_id` 查询参数的既有规则，鉴权开启时要求 `request:read` 且限于令牌所属租户，鉴权关闭时维持公开读取；查询字符串除 `tenant_id` 外不接受任何参数，未知或重复查询参数、缺失或冲突的租户目标返回 `400 {"error":"invalid_request"}`。成功返回 `200 application/json`，正文逐字节等于存储层 `export_audit_bundle` 从同一数据库快照产生的单行紧凑 JSON 文本（恰好一个末尾换行），不包响应对象、不重排字段、不美化缩进、不追加摘要。链头未推进时重复读取字节一致；之后新增状态事件只产生新证据包，绝不改变已渲染文本，也不泄露其他请求、主体、原始范围、幂等键、领取凭证或锚点秘密。请求编号格式非法、未知、跨租户或尚未受理统一返回 `404 {"error":"not_found"}`；请求存在但审计链尚未可靠落定、缺少所需历史锚点秘密或证据不可信时返回 `409 {"error":"audit_bundle_unavailable"}`，绝不返回半份文本；数据库不可读、快照读取失败或证据损坏返回 `503 {"error":"storage_unavailable"}`。该 GET 严格只读：不修改持久化证据、不写审计事件、不创建批次；非 GET 方法返回 `405 {"error":"method_not_allowed"}` 并带 `Allow: GET`，HEAD 不返回正文，更深路径为 `404 {"error":"not_found"}`。入口另支持 HTTP 条件读取：每个 200 响应携带强 ETag，取值为正文全部字节的 SHA-256，格式固定为双引号包围的 `sha256:` 加 64 个小写十六进制字符；相同正文在同一数据库中始终得到相同 ETag（含进程重启后），正文改变则 ETag 改变。请求可携带一个 `If-None-Match` 头（逗号分隔的实体标签列表）：当某个去除外围空白后的双引号标签与当前 ETag 完全相等，或标签为 `*` 且证据包当前可导出时，返回 `304`，不返回正文、`Content-Length: 0` 并携带相同 ETag；标签不匹配、多值均不匹配或使用 `W/` 弱标签时返回完整 200 正文。存在多个 `If-None-Match` 头、字段值为空、含控制字符、或不是合法双引号实体标签也不是 `*` 时，在鉴权、租户与查询参数校验通过后返回 `400 {"error":"invalid_request"}`，且不读取或改动存储；请求编号格式错误、未知、跨租户或证据包不可导出时仍按既有 404/409/503 结束，不返回 304，条件读取绝不写数据库、不生成新事件、不改变回执字节。
- `GET /requests/{request_id}/deletion-receipt`：只读公开该请求已固化的**删除执行回执**，调用方无需接触签名密钥即可取回首次落定的回执文本。租户沿用 `X-Tenant-Id` 非空优先、否则取 `tenant_id` 查询参数的既有规则，鉴权开启时要求 `request:read` 且限于令牌所属租户，鉴权关闭时维持公开读取；查询字符串仅接受 `tenant_id`，重复或任何其他查询参数、缺失或空租户返回 `400 {"error":"invalid_request"}`。成功返回 `200 application/json`，正文逐字节等于存储层 `get_receipt` 对同一租户与请求返回的规范单行紧凑 UTF-8 JSON 原文（固定字段顺序 `tenant_id`、`request_id`、`created_at`、`completed_at`、`scope_digest`、`attempt_digest`、`tag`，恰好一个末尾换行），不包响应对象、不重排字段、不美化缩进、不重新计算。重复读取、进程重建、并发读取以及旧、新回执密钥轮换前后均返回相同字节；正文不含主体、原始数据范围、幂等键、签名密钥、密钥指纹或执行凭据。请求存在但回执尚未生成、状态不允许生成回执或回执暂不可用返回 `409 {"error":"receipt_unavailable"}`；非法、未知或跨租户请求编号统一返回 `404 {"error":"not_found"}`；数据库不可用、记录损坏或文本不规范返回 `503 {"error":"storage_unavailable"}`，错误正文只含 `error` 字段。该 GET 严格只读：不创建回执、不注册密钥代次、不推进状态、不改写证据；非 GET 方法返回 `405 {"error":"method_not_allowed"}` 并只声明 `Allow: GET`，HEAD 不返回正文，更深路径为 `404 {"error":"not_found"}`。

- `GET /audit-health`：只读公开指定租户的**即时审计健康摘要**，复用存储层 `audit_health` 既有快照语义。请求不带 JSON 业务体，租户沿用 `X-Tenant-Id` 非空优先、否则取非空 `tenant_id` 查询参数的既有单值解析规则；查询字符串除单个 `tenant_id` 外不接受任何参数，未知或重复查询参数、缺失或空租户返回 `400 {"error":"invalid_request"}`。成功返回 `200 application/json`，正文为一行紧凑 UTF-8 JSON 加恰好一个末尾换行，字段固定依次为 `total`、`statuses`、`verified`、`unverified`、`reasons`：`total` 为该租户请求总数；`statuses` 依次含 `accepted`、`processing`、`completed`、`failed` 四个生命周期计数（缺省显式为零），其和恒等于 `total`；`verified` 与 `unverified` 互补且之和也恒等于 `total`；`reasons` 为 `{"reason","count"}` 列表，每个原因码只出现一次并按 Unicode 码点升序排列、`count` 为正整数，全量可信时为空数组且其计数之和等于 `unverified`。摘要来自单个一致只读事务，不创建巡检批次、不推进游标、不写业务、审计、锚点或密钥记录，并发提交、状态推进或巡检不会把不同事务的半套字段拼进同一响应；查询不存在的租户返回全零快照，不按缺失请求处理。数据库不可读写、簿记或证据损坏、无法取得一致快照时统一返回 `503 {"error":"storage_unavailable"}`，错误体只有 `error` 字段，绝不返回部分快照、伪计数、租户、请求编号、路径或 SQL 内容。非 GET 方法返回 `405 {"error":"method_not_allowed"}` 并带 `Allow: GET`，HEAD 不返回正文，未知或更深路径仍为 `404 {"error":"not_found"}`；鉴权开启时要求 `request:read` 且令牌所属租户只能查询自己的租户（跨租户为 `403`），令牌缺失、畸形或未知为 `401`，鉴权关闭时维持现有服务行为。

- `GET /audit-inspection`：按租户**批量巡检**已落定审计链（扫描模式），或按批次读取**逐批原因聚合指标**（指标模式），复用存储层 `audit_inspection` 与 `audit_inspection_metrics` 既有语义，不新增健康命令。租户沿用 `X-Tenant-Id` 非空优先、否则取非空 `tenant_id` 查询参数的既有规则；仅接受 `cursor`、`batch_id`、`limit` 查询参数（`limit` 缺省 100，仅接受 1 至 1000 的非布尔整数），`cursor` 与 `batch_id` 互斥：二者都缺省时创建新持久化批次，携带 `cursor` 从该批次的已提交位置续跑，携带 `batch_id` 时只读返回该批次指标且不创建、不推进、不写入任何记录。扫描成功返回 `200` 单行 JSON（恰好一个换行结尾），顶层恰含 `batch_id`、`next_cursor`、`finished`、`items`（顺序固定）：未完成时 `next_cursor` 为续跑游标字符串，结束时为 `null` 且 `finished` 为 `true`；`items` 按检查顺序列出本次核验的请求，每项恰含 `request_id`、`verified`（布尔）与 `reason`（核验为真时为空串，否则为稳定原因码）。指标成功返回 `200` 单行 JSON，恰含 `batch_id`、`scanned`、`verified`、`unverified`、`reasons`、`next_cursor`、`finished`：`scanned` 恒等于 `verified` 加 `unverified`；`reasons` 每项恰含 `reason` 与正整数 `count`，按原因码 Unicode 码点去重合并排序，全部核验通过时为空数组。参数缺失、重复、未知、类型错误或格式错误的 `cursor`、`batch_id` 返回 `400 {"error":"invalid_request"}` 且不创建、不推进批次；未知或跨租户批次统一返回 `404 {"error":"not_found"}`，不区分批次是否存在；存储或巡检簿记故障返回 `503 {"error":"storage_unavailable"}`，绝不返回半页或部分聚合。同一游标并发续查仅一个调用推进并返回新增 `items`，竞争调用返回空 `items` 与胜者提交后的 `next_cursor`，重试已用游标不重复汇报已落定项目。响应不含主体、原始范围、幂等键、worker、令牌、密钥、SQL 或路径。鉴权开启时仅接受 `request:reconcile` 角色且限令牌所属租户（令牌缺失、畸形或未知为 `401`，角色不足或跨租户为 `403`），鉴权关闭时维持公开调用；非 GET 方法返回 `405 {"error":"method_not_allowed"}` 并带 `Allow: GET`，HEAD 不返回正文，更深或并列路径仍为 `404 {"error":"not_found"}`。

存储层状态机（`RequestStore`，不经 HTTP 开放）：

- 生命周期固定为 `accepted -> processing -> {completed, failed}` 以及 `accepted -> failed`；受理记录自 `accepted` 开始，`completed` 与 `failed` 为终态。
- `transition(tenant_id, request_id, target_status)`：按迁移图推进。重复推进到当前状态是幂等空操作，返回当前状态记录且不追加状态、不改首次受理时间/编号/幂等回执。
- `get_status(tenant_id, request_id)`：按租户和请求编号返回当前状态记录，结构、字段顺序与受理回执一致（`request_id`、`status`、`created_at`），但 `status` 为最新状态、`created_at` 仍为首次受理时间；实例重建后结果一致。
- `list_requests(tenant_id, statuses=None, created_from=None, created_to=None, cursor=None, limit=None)`：租户范围的请求摘要分页查询，只读取已受理记录，不写库、不推进状态。`statuses` 仅接受 `accepted`、`processing`、`completed`、`failed` 若干不重复值（缺省为全部，规范化后顺序无关）；`created_from` 与 `created_to` 为 RFC3339 UTC，前者含边界、后者不含边界；`limit` 缺省 100，仅接受 1 至 1000 的非布尔整数。查询在一致快照中按 `created_at`、`request_id` 升序返回，外层恰含 `items` 与 `next_cursor`，每项恰含 `request_id`、`status`、`created_at`。`cursor` 为不透明续查值，绑定同一租户与规范化筛选条件，从末项后继续，结束时 `next_cursor` 为 `None`。空租户或非法筛选参数、跨租户或跨筛选条件复用游标，统一抛固定文案 `ValueError`（`request_listing_failed`）且不写库；存储故障或记录损坏统一抛固定文案 `OSError`（`request_listing_failed`），不返回部分列表。
- 并发推进同一请求时，仅允许迁移图允许的最终结果，底层锁冲突不会作为调用方错误泄露。

存储层跨重启可信锚点与全链核验（`RequestStore`，不经 HTTP 开放）：

- 背景：仅靠库内事件哈希与请求链头，拿到数据库文件者可重算全部事件、链头并自洽，无法区分真实时间线与整条伪造链。本能力以调用方在数据库之外保管的锚点秘密为外部可信锚点：`RequestStore(db_path, anchor_secret=...)`。锚点秘密只存在于构造进程内存中，绝不入库、回执、返回值、异常或日志，库内只存不可逆的 HMAC 输出与不可逆密钥指纹；锚点也无法由库内事件、链头或任何公开内容重算恢复。`anchor_secret` 省略时维持历史无锚行为，但其全链核验结论为不可信。
- 每次受理与每次实际状态变化，在**同一事务**内原子落定：有序事件、请求行链头、该事件的逐请求外部锚点（HMAC-SHA256，绑定租户、请求、序号、状态、发生时间、事件自身链哈希、前一锚点与锚点密钥代次）与文件级全局锚点头（按全库提交序号串联每一条锚点及其租户/请求/序号关联）。事件、锚点一一对应，全局提交序号在全库从 1 连续无缺；任一部分提交失败即整体回滚并抛固定文案 `OSError`，绝不返回成功、绝不留下可判完整的半成记录。幂等重复受理只回放冻结回执（只读），不写锚点。
- `verify_chain()` / `verify_audit_chain()`：只读全链核验，可无参核验整库，或 `verify_chain(tenant_id, request_id)` 核验指定请求（仍受全库全局锚点头约束）。检查事件顺序、序号连续、请求归属与租户关联、数据库链哈希逐环一致、请求行链头与当前状态一致、每条外部锚点按其锚定时代次在对应锚点秘密下认证、事件与锚点一一绑定、全局提交序号连续且重算的全局锚点头与落定值一致。重建实例通过 `RequestStore(db_path, anchor_secret=当前秘密, anchor_history_secrets={代次: 历史秘密, ...})` 提供当前与历史秘密；持当前秘密及所需历史秘密时旧代锚点与现用锚点分别核验成功。重复查询与核验绝不写入或改变记录。
- 任何事件删改、插入、调序、跨请求或跨租户替换，链头不一致，锚点损坏，锚点密钥代次关联被改，全局头被改，或提交中断（事件无锚点、锚点头缺失等）均返回 `False`。重建实例缺少某一历史代次秘密时，该代锚点无法认证，核验返回 `False`（诊断 `anchor_key_missing`），绝不以当前秘密代猜；攻击者即使重算并替换库内全部事件哈希、请求链头、锚点表与公开“锚点”，因不掌握外部秘密，伪锚点无法认证、全局头无法重算一致，伪造链仍判 `False`。
- `diagnose_chain()` / `diagnose_audit_chain()`：只读恢复诊断，返回稳定、无细节的原因码列表（可信时为空），如 `unanchored_database`（旧库无锚点）、`anchor_secret_missing`（未持秘密核验已锚定库）、`anchor_key_missing`（缺少某历史代次秘密）、`anchor_auth_failed`（锚点不认证/秘密错配/锚点伪造）、`anchor_head_mismatch`（全局头不一致）、`chain_hash_mismatch`、`chain_head_mismatch`、`event_order_invalid`、`event_unanchored`、`anchor_orphan`、`anchor_state_split`、`anchor_sequence_gap`、`request_association_mismatch`、`request_status_mismatch`、`anchor_meta_corrupt`、`anchor_row_corrupt`。诊断**只报告**不可信原因，绝不修复、回填、重算或覆盖任何事件、链头、锚点或代次关联。
- `audit_inspection(tenant_id, cursor=None, limit=None)`：只读批量审计完整性巡检，另经 `GET /audit-inspection` HTTP 入口开放（鉴权开启时要求 `request:reconcile` 角色且限本人租户），HTTP 层只做鉴权、租户与参数解析及错误码映射，不改写下列任何存储语义；不新增健康命令。按首次受理时间再按请求编号稳定扫描本租户全部请求（无论状态），返回恰好四个字段：`batch_id`、`next_cursor`（结束时为空值）、`finished`（布尔）与 `items`（逐项结果，按扫描顺序稳定排列；每项恰含 `request_id`、`verified`（布尔）与 `reason`（稳定原因码字符串，核验为真时为空串））。首次调用（无游标）创建可恢复的持久化批次；携带同一游标续查时沿用同一批次标识并从持久化位置继续，不重复汇报已落定项目，服务重启后顺序稳定。`limit` 缺省 100，只接受 1 至 1000 的非布尔整数。
  - 逐项核验与只读全链核验同一套证据：请求自身的事件顺序与数据库链哈希、请求行链头与当前状态、事件与锚点一一绑定、每条锚点按其锚定时代次认证，以及文件级封缄（单例全局头、密钥代次记录、全库提交序号连续与重算的全局锚点头）。正常请求核验为真且原因码为空；事件删改、插入、调序或跨请求、跨租户替换，链头、锚点或全局头损坏，缺少历史秘密、代次关联损坏或伪造链，旧库无锚点与未完成提交，逐项均核验为假并报告稳定原因码。
  - 巡检严格只读：只读取并核验已落定审计链，绝不修复、回填、重算或覆盖任何审计、锚点或密钥记录；仅写巡检簿记表（批次行、逐项结果与游标位置），每项结果与游标位置在同一事务落定，提交失败不返回半成结果。
  - 入口语义：`tenant_id` 为空或非字符串、`limit` 非法、游标为空/非字符串/格式未知（含对账批次游标）/指向不存在或跨租户批次，统一抛 `ValueError` 且不写库；存储不可用、批次或审计簿记损坏、批次提交失败统一抛固定文案 `OSError`，不返回半成结果。
  - 同游标并发续查：同一租户、同一批次、同一游标并发调用时，只有一个调用在单一事务内原子推进整整一页（巡检批次行、逐项结果与游标位置同一事务提交），获胜调用按既有扫描顺序返回本页 items 及获胜事务提交后的完整进度；竞争调用沿用相同返回形状但 `items` 为空列表，`next_cursor`/`finished`/`batch_id` 反映获胜事务提交后的位置。顺序重试、服务重启或批次结束后继续沿用持久化进度，已落定项目绝不重复汇报，结束游标始终为空值。并发推进只写巡检批次行、逐项结果与游标位置，绝不补偿执行尝试，也不改变请求状态、执行记录、审计链、锚点或回执。
- `audit_inspection_summary(tenant_id, batch_id)`：只读巡检批次摘要，只在存储层开放，不经 HTTP、不新增健康命令。调用者只传租户与批次标识（不是游标）；摘要不推进游标、不创建批次、不修复证据，也不写入任何业务或审计记录。
  - 输出为单行紧凑 JSON，末尾恰好一个换行；字段依次为 `batch_id`、`scanned`、`verified`、`unverified`，同一行随后给出 `next_cursor` 与 `finished`，不包含逐项结果。三个计数均为非负整数且已扫描数等于已核验与未核验之和；批次标识与游标只用字符串或空值（批次结束时 `next_cursor` 为空值），完成标记只用布尔值；不出现浮点数、负零或非有限数。
  - 入口语义：租户或批次标识为空、非字符串时抛 `ValueError` 且不写库；批次缺失或跨租户时抛 `AuditInspectionNotFound`，不泄露他租户批次是否存在；存储不可用、巡检簿记损坏或读取失败统一抛固定文案 `OSError`，绝不返回伪摘要。返回值、异常与日志只含批次计数、游标与稳定结果，不含主体、范围、密钥、SQL 原文或路径。
- `audit_inspection_metrics(tenant_id, batch_id)`：只读巡检批次按原因聚合指标，另经 `GET /audit-inspection` 的 `batch_id` 查询开放（鉴权开启时要求 `request:reconcile` 角色且限本人租户），HTTP 层只做鉴权、租户与参数解析及错误码映射，不改写下列任何存储语义；不新增健康命令。调用者只传租户与已有批次标识（不是游标）；指标不推进游标、不创建批次、不修复证据，也不写入任何业务或审计记录，整个聚合在单个只读事务内取一致快照，不出现半成字段或撕裂值。
  - 批次中每个请求只按当前记录贡献一次：成功核验计入已核验，未核验计入原因统计。输出为单行紧凑 JSON，末尾恰好一个换行，不引入额外空白；字段依次为 `batch_id`、`scanned`、`verified`、`unverified`、`reasons`、`next_cursor`、`finished`，不包含逐项结果。`scanned` 等于 `verified` 与 `unverified` 之和；`reasons` 为按原因码 Unicode 码点字典序排列的 `{"reason","count"}` 列表，相同原因合并计数、次数为正整数、空原因不进入列表，无原因时为空数组；批次标识与游标只用字符串或空值，完成标记只用布尔值；不出现浮点数、负零或非有限数。
  - 入口语义：租户或批次标识为空、非字符串时抛 `ValueError` 且不写库；批次缺失或跨租户时抛 `AuditInspectionNotFound`，不泄露他租户批次是否存在；存储不可用、巡检簿记损坏或读取失败统一抛固定文案 `OSError`，绝不返回伪指标。同一批次在重复读取、服务重启或批次结束后仍返回稳定聚合，已扫描项目不重复变化。未核验项目必须带非空稳定原因码：逐批指标发现未核验原因为空或非字符串时判为簿记损坏并抛固定文案 `OSError`，绝不把空原因折叠成成功或静默丢弃；已核验项目的空原因是巡检写入的成功标记，不进入原因列表。
- `audit_metrics(tenant_id, batch_ids)`：只读跨批次原因汇总，只在存储层开放，不经 HTTP、不新增健康命令。调用者只传租户与非空批次编号列表（编号均为巡检入口签发的批次标识，不是游标）；编号可以任意顺序传入，入口按编号 Unicode 码点字典序稳定处理；入口不创建批次、不推进游标、不修复证据，也不写入任何业务或审计记录。所有批次的批次行与逐项行在单个只读事务内取同一一致快照，不允许半成字段、撕裂计数或并发写入混入。已完成批次与尚未结束批次同样纳入汇总。
  - 输出为单行紧凑 JSON，末尾恰好一个换行，不引入额外空白；字段依次为 `batch_ids`、`batch_count`、`scanned`、`verified`、`unverified`、`reasons`、`all_finished`，不包含逐项或逐批请求结果。`batch_ids` 为排序后的批次编号字符串列表，`batch_count` 为其长度；三个计数为跨所给批次求和的非负整数，`scanned` 始终等于 `verified` 与 `unverified` 之和；`reasons` 为跨全部批次合并后的 `{"reason","count"}` 列表，按原因码 Unicode 码点字典序排列、次数为正整数，全部核验通过时为空数组；`all_finished` 为布尔值，恰在所有批次均完成时为真。批次编号只用字符串，输出不出现浮点数、负零或非有限数。
  - 入口语义：租户为空或非字符串，批次列表为空、非列表、含重复、含空元素或含非字符串元素时抛 `ValueError` 且不写库；任一批次未知或跨租户时抛 `AuditInspectionNotFound`，不泄露他租户批次是否存在；存储不可读写、簿记损坏（含未核验项目原因为空或非字符串）或聚合读取失败时统一抛固定文案 `OSError`，不返回部分聚合、伪指标，也不把空原因折叠成成功，不显示 SQL 原文、路径或秘密。同一批次列表重复读取（含顺序不同）结果字节一致、不写库、不改变任何游标位置，服务重建后仍稳定。返回值、异常与日志只暴露批次编号、原因码、计数与进度，不含主体、范围、秘密、凭证、SQL 或路径。
- `export_audit_bundle(tenant_id, request_id)`：只读审计证据包导出，支撑 `GET /requests/{request_id}/audit-bundle` HTTP 入口并继续作为存储层方法开放，不新增健康命令。按租户与请求编号把当前已落定链冻结为可供库外保存的单行紧凑 JSON 文本（恰好一个末尾换行），字段依次为 `request_id`、`status`（快照状态）、`events`（事件序列，每项恰含 `seq`、`status`、`occurred_at`、`chain_hash`）、`chain`（链摘要，恰含 `tenant_id`、`event_count`、`head`）、`anchors`（逐事件锚点，每项恰含 `seq`、`anchor_hmac`、`key_generation`）与 `generations`（该请求锚点实际引用的代次关联，每项恰含 `generation`、`key_fingerprint`、`effective_at`）。证据包只含证明所需的业务字段，不包含主体、原始范围、幂等键、worker、领取凭证或秘密；字符串保留原值，计数与代次为正整数，空值继续表达为空值，不出现浮点、负零或非有限数。
  - 每次导出冻结到当时的请求链头：之后新增状态事件产生新链头与新证据包，但不改变或否定既有证据包（其事件、锚点与代次是增长链的前缀，仍可核验）；同一链头重复导出字节一致，其他请求的事件或后续锚点密钥轮换都不改变本请求证据包的内容。
  - 导出严格只读：整个快照在单个只读事务内一致读取，并按与巡检相同的全链可信标准评估后才渲染，绝不写入、修复、回填、重算或覆盖任何记录。租户为空或非字符串抛 `ValueError` 且不产生证据包或写入任何记录；请求编号空值、非字符串、非法、未知或跨租户统一抛 `RequestNotFound`，不泄露存在性；链未锚定、缺历史秘密、证据损坏或不可信时抛 `AuditBundleUnavailable`；存储不可读写或读取事务失败时抛固定文案 `OSError`，绝不返回部分证据包或半成文本。
- `verify_audit_bundle(bundle_text, anchor_history_secrets)`：脱离数据库的异地核验，只在存储层开放，不经 HTTP、不新增健康命令。仅凭证据包文本与调用方在数据库之外保管的锚点秘密代次映射完全离线判断可信性，不需要数据库或存储实例，也始终不写库。检查文本边界、字段完整性、事件顺序、请求关联（快照状态、链摘要与末事件一致）、链哈希、逐事件锚点（按其记录代次对应的秘密认证）与代次绑定（所给秘密与包内不可逆指纹一致）。缺少数据库时有效证据包仍返回 `True`；事件、链摘要或锚点被重算替换后，因攻击者不掌握外部秘密，锚点无法认证，返回 `False`。
  - 入口语义：参数非字符串、映射非法（非映射、代次非正整数或秘密为空/非字符串）或文本格式损坏（缺末尾换行、多余换行、行内换行、JSON 不可解析、字段缺失或多余、类型或形状非法）时抛 `ValueError`；格式合法但认证不匹配、历史秘密缺失或代次证明不一致时只返回 `False`，绝不猜测秘密。
- `diagnose_audit_bundle(bundle_text, anchor_history_secrets)`：脱离数据库的异地可恢复诊断，只在存储层开放，不经 HTTP、不新增健康命令、不新增路由或落盘副本。仅凭证据包文本与调用方在数据库之外保管的锚点秘密代次映射完全离线运行，不需要数据库或存储实例，不创建批次，也始终不写库、不修改任何历史证据；诊断只读取传入材料，绝不猜测、修复、回填或重算证据包。
  - 输出为单行紧凑 JSON，末尾恰好一个换行，不引入额外空白；字段依次为 `trusted`（布尔）与 `reasons`（稳定原因码字符串数组，按 Unicode 码点字典序去重排列）。完全一致且每个锚点都由对应代次秘密认证时为 `{"trusted":true,"reasons":[]}` 加换行；缺少数据库时有效证据包仍判可信。输出只含布尔与稳定字符串，不出现浮点数、负零或非有限数，秘密材料绝不进入结果、异常或日志。
  - 原因码稳定且无细节：事件顺序、序号或锚点对应顺序不一致报告 `event_order_invalid`；重算的数据库链哈希不一致报告 `chain_hash_mismatch`；快照状态、事件计数或事件/锚点关联等请求关联不一致报告 `request_association_mismatch`；链摘要头与末事件链哈希不一致报告 `chain_head_mismatch`；所给秘密缺少锚点命名的某一代次时报告 `anchor_key_missing`，绝不以当前秘密代猜历史秘密；能定位对应代次但所给秘密与该代次不可逆指纹不一致（指纹与代次绑定不一致、代次关联伪造或代次记录重复）时报告 `anchor_generation_mismatch`；代次与指纹均可定位但锚点在对应秘密下不认证时报告 `anchor_auth_failed`。同一证据包同时存在多个相互独立的问题时返回全部可判定原因，单一错误不遮蔽其余问题。
  - 入口语义在与异地核验相同的形状与值域校验之上，进一步收紧单行输入边界：证据包必须是恰好一行规范紧凑 JSON（键值之间、逗号之后等处不允许字符串值之外的任何空白）并以恰好一个换行结束，对象后不允许尾随内容，同一对象成员名不得重复（重复成员按多余字段处理而非后者覆盖）。参数非字符串、映射非法（非映射、代次为布尔/非正整数、秘密为空或非字符串）或文本格式损坏（缺末尾换行、多余换行、行内换行、非紧凑的额外空白、尾随内容、重复成员名、JSON 不可解析、字段缺失或多余、类型或形状非法）时一律抛 `ValueError` 且不产生部分结果；字符串值内部的空白属于内容（只影响可信结论，不是格式损坏）。格式合法但历史秘密缺失、指纹错配、锚点不认证或链证明不一致时只返回不可信诊断（`trusted` 为假与相应原因列表），绝不猜测秘密。既有证据包导出与布尔核验行为（含其历史文本边界）保持不变，本次收紧仅作用于离线诊断入口。
- `resolve_scopes(tenant_id, subject_id, scopes)`：主体与数据范围解析，只在存储层开放，不经 HTTP、不新增健康命令、路由、解析表或后台扫描。入口接收租户、主体标识与范围标识集合，读取同一租户、同一主体的既有受理请求，在单个只读事务内取一致快照，返回规范化范围与冲突清单；不创建请求，不改变状态、执行记录、证据或巡检簿记，也绝不写库。调用前已提交的请求稳定纳入，调用后提交的不提前出现，并发受理或状态推进不会混入半个记录。
  - 范围标识采用业务选择器写法：`*` 表示全部数据，`集合名*` 表示整组数据，`集合:条目` 双段名称表示单个条目。两个名称段用冒号连接，名称只允许小写字母、数字、下划线、点和短横线，前后不得留白。规范化保留更强的选择：同一集合单条与整组并存时保留整组，`*` 出现后不再保留其他范围，整组选择不再保留同集合条目，具体条目按 Unicode 码点排序；范围为空、不是序列、含空值、含非字符串、含精确重复或含非法选择器一律抛 `ValueError` 且不写库。主体标识或租户为空、不是字符串、仅含空白时抛 `ValueError`，且不区分记录是否存在。
  - 冲突只比较同一租户和同一主体的既有受理请求，按首次受理时间再按请求编号稳定返回。`*` 覆盖所有范围，集合整组覆盖同组与同集合条目，同一具体条目互相覆盖，其余范围不冲突。返回字典键序固定为 `scopes`、`conflicts`；`scopes` 为规范化字符串列表，`conflicts` 为字典列表，子项键序固定为 `request_id`、`status`，只返回请求编号与当前状态，不返回主体、原始范围、幂等键、凭证、SQL 或路径。所有值只用字符串、整数、布尔或空值，不出现浮点、负零或非有限数；重复解析、实例重建与并发只读调用对同一快照返回相同字典。
  - 存储不可读写、记录损坏（受理行的状态或范围 JSON 损坏等）或快照读取失败时统一抛固定文案 `OSError`（`scope_resolution_failed`），绝不返回部分结果或半成清单；异常与日志只含稳定错误类别与计数，不暴露主体、范围、请求编号、SQL 或路径。既有受理、查询、状态、执行、证据、巡检与 HTTP 行为保持不变。
- 策略目录版本化管理（`RequestStore`，不经 HTTP 开放，不新增健康命令或路由）：普通规则目录与主体例外目录可发布为只读、可追溯的不可变版本，供保留期判定作为显式输入。三个入口只在存储层开放，绝不改变既有受理、状态、执行、回执、锚点、巡检与敏感信息边界。
  - `publish_policy_catalog(tenant_id, rules, exceptions)`：发布接收租户与两份目录（普通规则、主体例外）。发布时把范围选择器、保留天数、原因和主体例外按既有保留期语义规范化（选择器语法、非布尔非负整数天数、非空原因、必须含全数据 `*` 默认规则，策略号在两份目录内互不重复），保留规则优先级与排序（策略号按 Unicode 码点排序，不依赖传入顺序）。成功返回恰好两个字段：`version`（本租户从 1 起的正整数版本号）与 `effective_at`（该版本生效的 UTC RFC3339 时间）。同一租户相同规范化目录重复发布复用首次版本与首次生效时间（即使中间发布过其他版本），不重复写入；不同目录签发下一个连续正整数版本。版本只读不可改；发布只在版本行、全部规则行与全部例外行于同一事务全部写入成功后可见，任一写入失败回滚整体、不返回成功也不留下半成版本。同一租户相同规范化目录并发发布只落一次版本，所有调用得到同一版本与生效时间；不同目录并发发布仅一个版本获胜，竞争调用抛 `PolicyCatalogConflict` 且获胜版本不变。
  - `read_policy_catalog(tenant_id, version=None)`：读取该版本的普通规则和主体例外，返回单行紧凑 JSON 并以恰好一个换行结束，字段依次为 `version`、`effective_at`（UTC RFC3339）、`rules`、`exceptions`；规则按策略号排序，每条规则恰含 `policy_id`、`selector`、`days`、`reason`；例外按策略号排序，每条恰含 `policy_id`、`subject`、`selector`、`days`、`reason`。规则顺序、例外顺序及原因文本保持发布时的规范化结果，空例外目录为空数组。`version` 省略时使用当前最新版本；计数只用非负整数，不出现浮点数、负零或非有限数，不添加展示空白。版本不存在或跨租户（含无任何发布时读取最新版本）统一抛 `PolicyCatalogNotFound`，不泄露他租户存在性且版本不变。
  - `audit_policy_catalog(tenant_id)`：按版本编号升序返回历史摘要，返回 `{"versions":[...]}` 单行紧凑 JSON 并以恰好一个换行结束；每项恰含 `version`、`effective_at`、`rule_count`、`exception_count` 与 `status`，计数为非负整数，`status` 为布尔——唯一当前版本为 `true`、其余历史版本为 `false`；摘要不含主体明细。无发布的租户返回空数组。
  - 入口语义：租户为空、非字符串或仅含空白，两份目录或序列形状非法（非映射、缺 `*` 默认规则、跨目录策略号重复、选择器/天数/原因/主体绑定非法、版本为非布尔非正整数等）统一抛 `ValueError`（固定文案 `policy_catalog_failed`）且不写库、不产生半成品；并发竞争不同目录抛 `PolicyCatalogConflict`；版本不存在或跨租户抛 `PolicyCatalogNotFound`；存储不可读写、目录记录损坏、重复版本、孤儿行、非法形状或提交失败统一抛固定文案 `OSError`（`policy_catalog_failed`），不返回半成结果。读取与审计严格只读：在单个只读事务内取一致快照，不修复、回填、重算或覆盖既有目录，也不改变请求状态、执行记录与审计链；重复读取、实例重建后结果稳定。版本化目录可作为 `resolve_retention` 的显式输入，保留期判定与主体范围解析保持兼容，结果不因发布顺序改变。
  - `resolve_retention(tenant_id, subject_id, scopes, rules=..., exceptions=..., version=None)`：保留期判定入口，只在存储层开放，不经 HTTP、不新增健康命令或路由。入口仍接收租户、主体与范围的有序序列，范围规范化与优先级匹配保持既有语义（条目优先于集合、集合优先于全数据默认，主体例外优先于普通规则；同一优先级按策略编号 Unicode 码点顺序取首条；每个规范化范围独立匹配，保留天数取所有范围结果最大值；例外清单按规范化范围顺序稳定排列，原因文本保持目录原始内容）。目录来源二选一：`version` 省略时沿用两份调用期目录输入；`version` 给定时（非布尔正整数）从数据库读取该不可变版本，且两份目录参数必须同时省略，两种来源不得同时给出。给定版本与该主体既有受理请求在同一个只读事务的一致快照中读取；返回普通字典，键序固定为 `retention_days`、`policy_id`、`exceptions`、`reason`，值只用整数、字符串、列表与字典，不出现浮点、负零或非有限数，也不引入序列化空白。判定严格只读：不发布版本、不改变请求状态、执行记录、证据链或巡检游标，同一租户、主体、范围与版本在重复调用、实例重建或并发只读下结果相同；发布相同目录的版本号与生效时间复用既有语义，结果不因发布顺序或传入顺序改变。
  - 判定入口语义：租户、主体或范围为空、类型非法或范围不是有序序列，版本为布尔、非正整数，目录输入形状非法，或只给一份目录、两种目录来源同时给出时，统一抛 `ValueError`（固定文案 `retention_policy_resolution_failed`）且不写库、保持既有数据不变；指定版本不存在或跨租户不可见时抛 `PolicyCatalogNotFound`，不区分他租户是否存在、不推进版本；存储读取失败、目录记录损坏（版本行/规则行/例外行形状非法、内容指纹不一致、孤儿行等）或快照读取失败时统一抛固定文案 `OSError`（`retention_policy_resolution_failed`），不返回部分结果。命中例外清单每项只含所绑定主体（必为本次查询主体）、命中的规范化范围、天数与目录原始原因；异常与日志只含稳定错误文案与计数，不含主体、原始范围、秘密、SQL 原文或路径。
  - `resolve_retention_trace(tenant_id, subject_id, scopes, rules=..., exceptions=..., version=None)`：保留期判定的只读逐范围证据入口，默认只在存储层开放、不新增健康命令；其已发布版本证据另经只读 HTTP 入口 `GET /policy-catalog/retention-trace` 公开（仅接受已发布 `version`，不收请求体或内联目录）。入参与目录来源二选一规则与 `resolve_retention` 完全一致：传租户、主体与范围的有序序列，范围沿用既有选择器规范化与覆盖关系；`version` 省略时使用两份调用期目录，给定时只从数据库读取该已发布不可变版本，两种来源同时给出、只给一份目录或版本非法均为调用方错误。追踪严格只读：在单个只读事务的一致快照中与聚合判定读取同一目录版本与该主体既有受理请求，不发布版本、不写库，也不改变请求状态、执行记录、证据链或巡检游标；失败绝不写库。
  - 追踪结果为单行紧凑 JSON 文本，恰好一个换行结束，不添加任何展示空白。首段字段依次为 `catalog_source`（调用期目录为 `call_time`、已发布版本为 `published_version`）、`subject_id`（查询主体）、`scopes`（规范化范围，按规范化顺序）、`retention_days`（有效保留天数）、`policy_id`（最终胜出策略编号）、`reason`（最终原因，目录原文）、`exception`（最终胜出者是否为主体例外的布尔）；随后为 `scope_evidence`，逐范围证据按规范化范围顺序排列，每项字段依次为 `scope`（规范化范围）、`level`（命中层级：`entry`/`group`/`all`）、`policy_id`（该范围适用策略）、`exception`（该范围命中是否为例外的布尔）与 `retention_days`（该范围保留天数）。条目、集合整组与全数据默认的层级优先级保持不变，主体例外优先于普通规则，同一优先级按策略编号 Unicode 码点序确定胜者；多范围汇总保留天数取各范围结果最大值，跨范围并列时按规范化范围顺序取首个胜者。聚合与追踪的最终胜出策略编号、原因与例外标记都取该胜者，同一范围内继续沿用既有规则。字符串保留原文，布尔值保持布尔值，计数为整数，不出现浮点数、负零或非有限数；结果可返回查询主体与规范化范围，但绝不返回调用者传入的原始范围序列。

- 写入闸门：仅当已落定证据在所配置当前秘密及历史代次秘密下完整可信时，持秘密实例才允许追加；旧库（有事件无锚点）不会被追溯回填锚点（追加时在同事务以不可逆指纹补登记第 1 代且不改写既有锚点归属），持秘密实例对旧库的写操作抛固定文案 `OSError`，无秘密实例对已锚定库的任何追加/受理同样抛 `OSError`，错误秘密或轮换后仍持旧秘密的实例无法写入（先认证既有锚点）。历史无秘密实例对历史无锚库的既有行为保持不变。
- 锚点密钥代次轮换 `rotate_anchor_key(retired_secret, new_secret)`：只在存储层开放，不经 HTTP、不新增健康命令。以“退用秘密 + 启用秘密”在单一事务原子切换一个代次，成功返回恰好两个字段：`generation`（正整数，新现用代次）与 `effective_at`（该代次生效的 UTC RFC3339 时间）。轮换生效后新锚点关联新代次；已有锚点继续关联各自生成时的代次，绝不追溯改写。历史秘密由调用方在数据库之外保管，数据库只保存代次、生效时间与不可逆 SHA-256 指纹。
  - 库内从未落定锚点时首次轮换，在同一事务登记第 1 代（退用秘密）与第 2 代（启用秘密），返回第 2 代；首次落锚前已轮换时首个锚点即为第 2 代。代次表为空的旧锚定库（锚点为历史第 1 代归属）仅在退用秘密能在事务内重放认证整条已落定链后才补登记 1/2 代，未锚定旧库或认证不通过时抛固定文案 `OSError` 且不写库。
  - 相同轮换（与产生现用代次完全相同的“退用→启用”组合）幂等返回首次代次与首次时间，相同组合的并发调用得到同一首次结果。
  - 并发提交不同启用秘密时仅首笔生效，竞争失败方抛 `AnchorKeyConflict`，原代次不变。
  - 退用秘密已登记但非现用代次（且非现用代次的直接前驱）、启用秘密已登记（复用旧秘密）、退用/启用秘密为空值或类型非法、两秘密相同，或实例未配置锚点秘密时抛 `ValueError`，且不提交任何变化。
  - 构造参数 `anchor_history_secrets` 必须是代次（非布尔正整数）到非空秘密字符串的映射，否则抛 `ValueError` 且不写库；历史秘密只能与当前 `anchor_secret` 一同提供。代次记录损坏、数据库读写失败或轮换提交失败统一抛固定文案 `OSError`，不显示半成代次。服务重启后代次、生效时间与既有审计结论保持稳定；轮换只在内存更新现用秘密，不向数据库写入任何秘密材料。
- 入口语义：`tenant_id` 为空、非字符串抛 `ValueError`；请求编号空值、非字符串、非法、未知或跨租户统一抛 `RequestNotFound`，不泄露存在性；只给请求编号不给租户抛 `ValueError`；存储不可用或锚点状态损坏抛固定文案 `OSError`。返回值、异常与日志只含请求编号、状态、时间与稳定原因码，不含主体、范围、密钥、SQL 原文或路径。
- 执行编排路径（首次领取进入 `processing`、`finish_claim` 终态、`reconcile_execution` 补偿、`reconcile_batch` 逐项收敛）产生的每次实际状态变化都在同事务锚定；受理、状态、执行、对账、健康与其他既有 HTTP 行为全部保持不变。

存储层执行编排（`RequestStore`；除 `reconcile_execution` 与 `reconcile_batch` 同时支撑对应 HTTP 入口外，均不经 HTTP 开放）：

- `claim_next(tenant_id, worker_id, lease_seconds)`：原子领取下一个可执行请求。`tenant_id`、`worker_id` 为非空字符串，`lease_seconds` 为 1 至 3600 的非布尔整数秒。候选为 `accepted` 请求及最新租约已过期的 `processing` 请求，按受理时间再按请求编号取最前者；首次领取使请求进入 `processing` 并开始第 1 次尝试，过期重领开始下一次尝试且不改变首次受理时间、编号或当前状态。同一请求同一时刻只有一个 worker 持有有效租约。成功返回恰好三个字段：`request_id`、不可预测的 `claim_token`、UTC RFC3339 的 `lease_expires_at`；无候选返回 `None`。worker 身份只校验不持久化，领取凭证只返回一次、绝不入库（仅存散列）或出现在日志中。
- `finish_claim(tenant_id, request_id, claim_token, result)`：以终态完成当前租约。`result` 只接受 `completed` 或 `failed`。凭证必须对应该租户该请求当前未过期、未释放的租约；终态状态与审计链事件、尝试结果记录、凭证释放在同一事务提交。返回状态记录（`request_id`、`status`、`created_at`）。
- `renew_lease(tenant_id, request_id, claim_token, lease_seconds)`：以领取凭证续期当前有效租约，只在存储层开放，不经 HTTP。`lease_seconds` 为 1 至 3600 的非布尔整数秒；成功只返回 `request_id` 与新的 UTC RFC3339 `lease_expires_at` 两个字段（顺序固定），不含浮点、负零或非有限数，实例重建后读取同一值。续期只把当前未释放租约的到期时间推进到本次事务提交时间加上续期秒数，请求状态、尝试序号、审计事件、回执与巡检簿记都不变，也不产生新尝试或新凭证；连续续租每次都按各自提交时间产生新的到期时间，同一凭证并发续租只提交一个新到期时间，竞争调用取得相同结果，底层锁冲突不外泄。续期后的凭证继续用于既有完成入口；到期未续的租约仍由既有对账补偿，迟到续租不复活已释放尝试。
- `transfer_claim(tenant_id, request_id, claim_token, lease_seconds)`：执行租约的安全交接入口，只在存储层开放，不经 HTTP、不新增健康命令或路由。持有当前有效领取凭证的调用方在单一原子事务中把它替换为新的不可预测单次凭证，并把同一执行尝试的到期时间改为本次提交时刻加 `lease_seconds`（参数沿用 `renew_lease`，为 1 至 3600 的非布尔整数秒）。成功返回恰好三个字段（顺序固定）：`request_id`、新的 `claim_token` 与新的 UTC RFC3339 `lease_expires_at`。交接不创建尝试，不改变状态、受理与事件时间、尝试、审计、锚点、回执、墓碑、策略目录或任何查询，执行日志只反映新到期时间。新凭证只在成功返回值中出现一次，数据库只存其 SHA-256 散列，异常、返回值与日志都不含新旧凭证、worker、主体、范围、SQL 或路径；新凭证继续适用于 `renew_lease`、`finish_claim` 与再次 `transfer_claim`，旧凭证在提交后立即失效。相同旧凭证并发交接至多一个成功，其余抛 `ClaimConflict`；交接与 `finish_claim` 并发时由提交顺序唯一决定成功者，后提交者冲突。过期重领、对账补偿、并发领取与终态结果语义不变；重启重建后交接结果继续有效。
- `get_execution_log(tenant_id, request_id)`：按租户与请求编号返回执行尝试列表，按尝试序号（从 1 递增）排列。每条恰含 `attempt_number`（正整数）、`claimed_at` 与 `lease_expires_at`（UTC RFC3339 字符串）、`result` 与 `completed_at`（完成后为终态与完成时间，进行中或被过期放弃的尝试为空值）。返回值只含字符串、整数与空值，不含 worker 或领取凭证。
- `reconcile_execution(tenant_id, request_id)`：按租户和请求编号对账执行结果，返回既有状态记录（`request_id`、`status`、`created_at`）；该方法同时经 HTTP（`POST /requests/{request_id}/reconcile`，要求 `request:reconcile` 角色）开放，HTTP 层只做鉴权、租户与编号解析及错误码映射，不改写下列任何存储语义。
  - `accepted`（含无任何执行尝试）时只返回现状：不创建记录、尝试或回执，也不产生任何变化。
  - 仍有有效租约的 `processing` 请求保留进行中尝试，不提前写终态、不生成新尝试。
  - `completed` 或 `failed` 的重复对账幂等：保留首次终态结果与同一状态记录；执行记录中存在多个终态时保留最早完成的结果，后续重复终态记为 `failed` 且不改请求状态。
  - 最新租约已过期且无其他有效租约（含无结果且无租约、或无任何可解释尝试）的 `processing` 请求，在同一事务内把全部未完成尝试补偿为 `failed`（完成时间为 UTC RFC3339，且每条只写一次），并把请求状态收敛为 `failed`；执行记录已含终态尝试时，以最早完成结果收敛，死租约凭证随补偿一并释放。
- `claim_next` 的领取边界收紧：仍按受理时间再按请求编号竞争可执行请求；候选仅为 `accepted`，以及具有可解释的已过期租约历史（至少存在一次尝试、最新租约已过期、且不存在仍在租期内的未完成尝试）的 `processing` 请求，过期重领生成递增的新尝试。无可解释租约或尝试的 `processing` 请求不得领取，交由 `reconcile_execution` 收敛。
- `reconcile_batch(tenant_id, cursor=None, limit=None)`：按租户批量对账待收敛请求，可携带可选游标与批次上限（缺省 100，1 至 1000 的非布尔整数），另经 `POST /reconcile` HTTP 入口开放（鉴权开启时要求 `request:reconcile` 角色），HTTP 层只做鉴权、租户与参数解析及错误码映射，不改写下列任何存储语义。首次调用（无游标）创建持久化批次并按受理时间再按请求编号稳定扫描；携带游标时恢复该游标对应的持久化批次，从已提交位置续跑，同一游标重试沿用同一批次标识。返回恰好四个字段：`batch_id`（字符串）、`next_cursor`（结束时为空值，否则为字符串游标）、`finished`（布尔，表示是否已扫完全部行）与 `items`（逐项记录列表，按扫描顺序稳定排列；每项恰含 `request_id` 与 `status`）。返回值中时间与游标只用字符串、计数与尝试序号只用整数、空值保持空值，不出现浮点数、负零或非有限数。
  - 批次首次扫描跳过 `accepted` 请求：不创建尝试、回执或额外状态事件，但游标位置仍向前推进，使该请求不会被重复扫描。
  - 仍有有效租约的 `processing` 请求保持处理中，不提前完成也不生成新尝试；租约过期、无结果或无可解释租约的 `processing` 请求按 `reconcile_execution` 既有规则在同事务内补偿为 `failed`（执行记录已含终态时以最早完成结果收敛）。
  - 可恢复游标持久化在数据库中：重复扫描、对账或服务重启后，同游标重试从持久化位置续跑，已落定的逐项状态不重复写入。每项的状态、尝试、租约、批次逐项记录与游标位置在同一事务落定，提交失败不返回半成结果、不留下半成记录。
- `migrate_execution_leases(tenant_id, cursor=None, limit=None)`：旧版执行租约数据的可恢复批量升级入口，只在存储层开放，不经 HTTP、不新增健康命令或路由。调用时传租户、可选游标与批次上限（缺省 100，1 至 1000 的非布尔整数）。首次调用（无游标）创建持久化批次，按请求受理时间再按请求编号稳定扫描本租户**携带旧版租约记录**的请求；携带同一游标续查沿用同一批次标识并从持久化位置继续，服务重启后进度不丢。返回**一行紧凑 JSON 文本**（字段依次为 `batch_id`、`next_cursor`、结束时为空值、`finished` 布尔、`items`）并以恰好一个换行结束；逐项恰含 `request_id`、`attempt_number`（该请求恢复出的当前最新尝试序号）与 `outcome`（稳定结果码：补写簿记为 `upgraded`，簿记已齐备无需补写为 `present`），不返回 worker 或领取凭证。
  - 升级只补齐可恢复的租约簿记：旧版尝试行按原领取时间、到期时间、尝试结果与完成时间原样补入当前尝试簿记；仅当请求仍为 `processing`、最新旧尝试未完成且在升级事务时刻仍在租期内、当前不存在凭证行且当前簿记无更新尝试时，才恢复其唯一的在租凭证散列行。请求状态、受理时间、尝试结果、审计链、锚点、回执与领取候选一律不变，也绝不产生第二份租约；没有有效租约的处理请求仍交给既有 `reconcile_execution` 收敛。
  - 升级幂等且可恢复：每个请求的旧版租约在本租户任意批次中最多升级一次（逐项表带租户级请求唯一标记），已完成项目不重复写入；重复迁移返回空项并结束，空批次也落定稳定进度。升级后重建实例保持同一租约状态，恢复出的有效凭证仍可续期与完成，过期重领仍生成递增的新尝试；迁移不改变领取候选和对账结果，续期到期时间仍以事务提交完成时刻加续期秒数计算，同一凭证并发续期只接受一个新到期时间、竞争调用取得相同结果。
  - 整页（批次创建/解析、每项补写、逐项记录与游标位置）在单一事务原子提交，提交中断不返回半批结果、不留下半成记录，下次续查只补做未落定项目。同一租户、同一批次、同一游标并发续查时只有一个获胜事务返回本页项目；竞争调用不写任何内容，以空 `items` 复用获胜事务提交后的 `next_cursor`/`finished`/`batch_id`。
  - 入口语义：`tenant_id` 为空或非字符串、`limit` 非法、游标为空/非字符串/格式未知（含对账或巡检批次游标）/指向不存在或跨租户批次，统一抛 `ValueError` 且不写库（不区分批次是否存在，不泄露他租户批次存在性）；数据库不可读写、旧租约记录损坏（尝试序号不连续、时间非法或顺序倒置、凭证散列损坏、结果非法、结果与完成时间分裂、旧租约挂在 `accepted` 请求下、旧行与既有当前行矛盾）或提交失败，统一抛固定文案 `OSError`（`execution_lease_migration_failed`），不返回半成结果。返回值、异常与日志只暴露批次、游标、请求编号、尝试序号、计数与稳定结果码，不含主体、范围、凭证、SQL 或路径。
- 服务重启后租约与尝试记录继续有效；并发领取、续期、完成与对账都在同一事务原子提交状态、尝试与租约，不会形成两个同时有效的租约，锁冲突不泄露底层数据库错误。

存储层删除回执（`RequestStore`，不经 HTTP 开放）：

- `generate_receipt(tenant_id, request_id, key)`：为已完成删除且执行记录落定的请求生成外部可核验的删除回执。只有状态为 `completed` 且最早终态尝试记录为 `completed` 的请求可取得回执；`accepted`、`processing`、`failed` 或无落定执行记录的请求统一抛 `ReceiptUnavailable`。多个终态尝试存在时回执关联最早完成的执行结果，后续重复终态不改变回执内容。
  - 回执为单行紧凑 JSON（固定字段顺序，恰好一个末尾换行），依次含 `tenant_id`、`request_id`、`created_at`（首次受理时间）、`completed_at`（最终完成时间）、`scope_digest`（范围承诺摘要）、`attempt_digest`（完成尝试摘要）与 `tag`（认证标签）；时间为 UTC RFC3339，摘要与标签均为 64 位小写十六进制。回执只含业务字段，不暴露主体、原始范围、幂等键、worker、领取凭证、SQL 或路径；不新增任何密钥标识字段，既有回执的字段、摘要、标签、换行与首次生成字节保持一致。
  - 认证标签使用调用方在数据库之外保管的密钥 `key`（非空字符串）以 HMAC-SHA256 计算；密钥材料绝不进入数据库、回执、异常或日志。
  - 首次生成时把所给密钥登记为该租户的现用密钥（第 1 代），与回执行在同一事务落定，也不改变状态、尝试、租约或审计记录。轮换后只接受现用密钥生成新回执：只要租户已登记密钥代次，旧代或外租户密钥对任何无回执请求（无论其状态）的生成都先抛 `ReceiptKeyConflict` 且不写库、不改状态、执行记录或回执；尚无任何代次时仍先按既有规则判定回执可用性，首代登记只随回执行同事务落定。既有回执重复生成（无论使用哪个密钥）仍返回字节一致的首次回执，并发生成只落一份，实例重建或服务重启后内容不变。回执记录损坏或存储不可用时抛固定文案 `OSError`，绝不回填、重算或覆盖已有回执。
- `verify_receipt(receipt_text, key)`：核验回执文本与密钥。仅当文本格式合法（紧凑 JSON、固定字段、**恰好一个末尾换行**——缺换行或多余换行均为格式非法，抛 `ValueError`）、与已落定回执记录逐字段（逐字节）完全一致、所给密钥属于该租户已登记的某一密钥代次、且认证标签在该密钥下重算一致时返回 `True`；字段、标签、时间、请求或租户关联被替换，或格式合法但认证不匹配时一律返回 `False`——请求记录存在不能替代认证结果，请求或回执不存在同样只返回 `False`，核验绝不修复任何数据。轮换后旧回执仍可用原（旧代）密钥验证；旧密钥对新回执、新密钥对旧回执、以及其他租户的密钥一律认证不匹配返回 `False`。核验不写入、修复、回填、重算或覆盖任何数据。
- `rotate_receipt_key(tenant_id, retired_key, new_key)`：可恢复的回执密钥轮换，只在存储层开放，不经 HTTP、不新增健康命令。针对租户以“退用密钥 + 启用密钥”完成一次原子轮换，返回恰好两个字段：`generation`（正整数，新现用代次）与 `effective_at`（该代次生效的 UTC RFC3339 时间）。
  - 首次生成回执时已自动登记现用密钥为第 1 代；尚无任何现用代次（从未生成过回执）时，首次轮换在同一事务登记第 1 代（退用密钥）与第 2 代（启用密钥），返回第 2 代；轮换前不存在旧回执，旧回执按其生成时密钥所在代次核验。
  - 相同轮换（与产生现用代次完全相同的“退用→启用”组合）幂等返回首次代次与首次时间；轮换后新回执只接受现用密钥签名，旧代密钥不得生成新回执，旧回执不得重写或补发。
  - 并发只产生一个现用代次：并发提交不同启用密钥时只有首个事务生效，竞争失败方抛 `ReceiptKeyConflict`，原代次不变；相同组合的并发调用全部得到同一首次结果。
  - 退用密钥已登记但不是现用密钥、重复使用已被取代的轮换组合，或启用密钥已登记（复用旧密钥）时抛 `ReceiptKeyConflict`，不提交任何变化；租户、退用密钥或启用密钥为空/类型非法、两密钥相同，或已存在代次但退用密钥不指向任何已登记代次（“缺少代次”）时抛 `ValueError`，且不提交变化。
  - 服务重启后代次、轮换时间与历史回执仍可读取；轮换与回执生成各自在单一事务原子提交，未完成轮换绝不可能显示为已生效，不返回半成代次。持久化只保存不可逆密钥指纹（SHA-256）、代次与时间，密钥材料绝不写入数据库、结果、异常或日志。
- 回执错误语义：生成入口的租户或密钥为空、类型或格式非法抛 `ValueError` 且不写库；请求编号为空值、非字符串、非法、未知、跨租户或尚未受理统一抛 `RequestNotFound`，不区分记录是否存在（不泄露存在性）；请求删除未完成或执行记录未落定抛 `ReceiptUnavailable`；使用非现用密钥要求新回执抛 `ReceiptKeyConflict`；核验入口参数非法抛 `ValueError`，文本格式合法但认证不匹配返回 `False`，存储不可用、回执或密钥记录损坏抛固定文案 `OSError`。轮换与生成中的数据库不可用、记录损坏或原子提交失败统一抛 `OSError`，不返回半成代次或半份回执。

执行编排错误语义（在既有错误语义基础上补充）：

- 入口参数、租期或终态不满足值域：抛 `ValueError` 且不写库。
- 领取凭证不存在、过期、已释放或跨租户/跨请求使用，或对无有效租约的请求完成（含对账释放死租约后再用旧凭证完成）：抛 `ClaimConflict` 且不改变状态、尝试或证据。
- 执行记录查询与对账中请求编号缺失、空、非字符串、非法、不存在或跨租户：统一抛 `RequestNotFound`，不区分记录是否存在；对账租户为空或非字符串抛 `ValueError`，不改变状态、尝试或回执。
- 批量入口 `reconcile_batch` 的租户为空或非字符串、上限非 1 至 1000 的非布尔整数、游标为空/非字符串/格式未知/指向不存在或跨租户批次：统一抛 `ValueError` 且不写库（未知游标格式也按非法处理，不区分批次是否存在）；数据库不可读写、批次或执行记录损坏或批次提交失败：统一抛固定文案的 `OSError`，不返回半成结果。
- `finish_claim` 在请求编号未知或跨租户、且凭证同时无效（未知、已释放或过期）时，稳定先抛 `RequestNotFound`；对确实存在的请求使用无效凭证仍抛 `ClaimConflict`，合法有效凭证跨请求/跨租户使用仍抛 `ClaimConflict`，且不改变状态、尝试或证据。
- `renew_lease` 的租户空值或非字符串、续期秒数空值/非整数/布尔/浮点或不在 1 至 3600 范围：抛 `ValueError` 且不写库；请求编号空值、非字符串、非法、未知或跨租户：抛 `RequestNotFound`（先于一切凭证校验）；凭证不是非空字符串、不存在、已过期、已释放或跨请求使用，或目标请求非处理中、无未释放有效租约：抛 `ClaimConflict` 且不改变状态；存储不可读写、租约记录损坏或原子提交失败：抛固定文案 `OSError`，不返回半成到期时间。
- `transfer_claim` 的参数值域沿用 `renew_lease`：租户空值或非字符串、秒数空值/非整数/布尔/浮点或不在 1 至 3600 范围抛 `ValueError` 且不写库；请求编号为空、非字符串、格式非法、未知或跨租户稳定抛 `RequestNotFound`，且先于凭证检查；凭证为空、非字符串、未知、过期、已释放、跨请求或跨租户，或目标不是持有有效未完成租约的 `processing` 请求时，抛消息为 `claim conflict` 的 `ClaimConflict` 且不改记录；数据库不可读写、租约损坏或提交失败时抛消息为 `execution_lease_transfer_failed` 的 `OSError`，不返回半枚凭证、半成到期时间或部分变化。
- 数据库不可创建、读写失败、执行记录损坏或补偿提交失败：统一抛固定文案的 `OSError`，不返回半成结果、不留下半成记录。

错误语义（存储层异常类型稳定，回执、返回值与日志只暴露请求编号、状态、时间与稳定错误类型，不含主体、范围、幂等键、其他租户信息、SQL 原文或路径）：

- 受理、推进或查询中，除请求编号外的参数非法、范围为空或重复、目标状态越界：抛 `ValueError` 且不写库。
- 请求编号非法、请求不存在、跨租户访问或尚未受理：统一抛 `RequestNotFound`，不区分记录是否存在。
- 已定义状态之间发生非法迁移（含从终态继续推进）：抛 `InvalidStatusTransition`，原状态不变。
- 同一幂等键提交不同主体或范围集合：抛 `IdempotencyConflict`，首次受理回执不变。
- 存储路径为空或非字符串：抛 `ValueError`；数据库不可创建、目录不可写、读写失败或内容损坏：统一抛固定文案的 `OSError`，状态写入失败时不返回半成状态。

HTTP 错误响应均为只含 `error` 字段的单行 JSON，使用稳定错误码：

| HTTP | error |
| --- | --- |
| 400 | `invalid_request`（非法 JSON、空值/非字符串、空范围或重复范围） |
| 401 | `unauthorized`（仅启用鉴权：缺少/畸形 `Authorization` 或令牌未配置） |
| 403 | `forbidden`（仅启用鉴权：角色不足或目标租户与令牌 `tenant_id` 不符） |
| 404 | `not_found`（缺失请求、非法编号、跨租户查询、未知路径） |
| 405 | `method_not_allowed`（不支持的请求方法；HTTP 不提供状态推进端点） |
| 409 | `idempotency_conflict`（同键不同主体或范围集合） |
| 409 | `audit_bundle_unavailable`（审计链尚未可靠落定、缺少所需历史锚点秘密或证据不可信） |
| 503 | `storage_unavailable`（数据库不可创建、读写失败或内容损坏） |

受理在响应返回前已完成事务提交；关闭服务并用同一数据库重启后，受理回执字节一致、当前状态记录一致。健康命令、HTTP 错误码与回执格式保持兼容。响应、日志与异常只暴露稳定错误码，不包含主体、范围、幂等键、SQL 原文或文件路径。
